## Spec-driven development

- 2026-11-15: `.kiro/specs/reclaim/requirements.md` drafted by the Kiro IDE agent from Tanvir's written plan, a mockup board and follow-up chat decisions. 30 requirements with EARS-style acceptance criteria.
- Decisions changed during requirements, before any code: the offer notification trigger was replaced by a hiding cloth Ghost (Tanvir's idea, to fix the risk that judges miss a self-expiring notification); hover on the Ghost causes a storm flicker. Agent added a WCAG 2.3.1 flash limit to that effect, a touch two-tap rule and keyboard access. Sound moved to the last phase.
- 2026-11-15 (revision 3): Tanvir replaced the hiding ghost with a Day bat that flies around the shop. The cursor becomes a reaching hand only over the bat; hover brings lightning and warning signs; clicking catches the bat, which jerks its head around, lunges and covers the screen with its wings while the Reveal happens in the dark. The Kiro-style sheet ghost moved to the climax. Product views now show ghostly events in the shop behind them. The agent rewrote Requirements 8–9 and replaced every Ghost reference across the spec with a script, then checked that none were left.
- 2026-11-15 (revision 2): story/psychology section added to the spec; the Ghost became an original homage to Kiro's ghost mascot (agent flagged that embedding the official logo may conflict with Rules section 11); photos replaced by real-time 3D "live objects" (Req 31); a one-Anomaly-at-a-time "Stage" rule added for pacing; new consequences for shoes, watch, mirror, typewriter, telephone, photo, bats and a crawling severed hand; ten more anomalies (Req 32) and a postcard + director mode (Req 33).

- 2026-11-15: `.kiro/specs/reclaim/design.md` written by the Kiro IDE agent from the approved requirements. It defines the layer stack (DOM, decals, darkness overlay, shared WebGL canvas, hit proxies, overlays, inspection canvas), a pure reducer as the testable story core, a Director for Stage/light/attention/acts, a shared decay shader for in-place damage, and a property-based test plan mapped to requirement numbers. While designing, the agent found that one WebGL context cannot sit both under the product view's blur and above it, and changed Requirement 27.2 to allow a second context only during inspection.

- 2026-11-15, task 1 (setup): before installing anything, the agent searched the web and found that Node 20 on the dev machine had reached end of life on 2026-04-30; Tanvir upgraded to Node 26 LTS. The agent also turned off Fastify's default request logs because they include client IP addresses (Requirement 24.4).

## Property-based testing

_(which requirements, what it caught)_

- 2026-11-15, task 2.3: the first version of the property tests passed, which looked fine. The agent added a coverage test that samples the event generator and counts how many runs reach each story phase. It showed only 55 of 1000 random runs ever reached the Haunted state, so the properties about checkout, acceptance and the ending were almost never exercised. The generator was rewritten to mix random events with scripted visitor actions (catch the bat, buy a few items, go through checkout). With that change, the coverage test enforces minimum counts, and all properties still hold. Lesson for the write-up: a green property test is not evidence on its own; measure what the generator reaches.

- 2026-11-15, task 3: the persistence round-trip property failed once on a random seed: a Lasting mark with rotation `-0` came back from JSON as `0`, so the loaded state was not equal to the saved one. A unit test would never have tried `-0`. The agent wrote two regression tests, confirmed they fail without the fix, then made the reducer normalize `-0` and reject non-finite mark coordinates. The new contrast test on the design tokens also failed for the haunted button outline (1.6:1 against cards); a dedicated outline colour was added so both palettes pass WCAG AA.

- 2026-11-16, tasks 3–12 (single long agent session in Kiro IDE, Tanvir granted blanket execution permission). Findings that changed the code:
  - **Quality gate by screenshot:** the agent drove Playwright to screenshot the Day shop, the product view and the haunted grid, then looked at the images itself. That showed the pocket watch rendering well, and the doll dress washing out pink, the shoes too flat and the typewriter over-dusted. Materials and framing were tuned from the screenshots.
  - **WebGL context limits found while designing:** native `<dialog>` lives in the browser's top layer, so no canvas can paint above it. The inspection therefore uses its own canvas, and environment maps are set per scene, because a PMREM texture cannot be shared across WebGL contexts.
  - **The API allowlist property test failed:** Fastify's default JSON validation silently strips unknown fields and accepts the request. AJV was set to reject them.
  - **e2e found three real bugs:**
    1. A second quick Add to Cart lost its Consequence, because the Stage refused it. Visitor Consequences now queue.
    2. Fast typing followed by Escape raced async router navigations. The shop query moved to a synchronous store mirrored with `replaceState`.
    3. A quick second tap on the bat read stale React state. The tap handler now reads the store.
  - **React Compiler lint rules (react-hooks 7):** they flagged refs written during render, setState in effects, `Math.random` in render and hook-value mutation. Each was refactored rather than silenced.

- 2026-11-21, realism and feedback round (Kiro IDE agent, same blanket permission). Tanvir reviewed the build and asked for realistic objects, a scarier bat, a skeleton-hand cursor, clear cart confirmation and stock limits, a single fast checkout ghost and a shadow lady in the mirror. What the agent did and found:
  - **Code-only realism:** generated surface textures (wood grain, leather, knit, fur, paper, metal, ceramic, wax) feed the shared material factory, and the hero became a live 3D still life. After the Reveal a procedural ruined street (seeded skyline with window holes, a moon, a fire glow) stands behind it. No photos or third-party models.
  - **Screenshot review caught layout bugs:** the first ruined skyline ran behind the hero copy and made the subtitle unreadable, because the shared canvas paints over the DOM. The skyline now starts right of the copy. When the hanging bat was flipped, its legs read as rabbit ears; the wings were redrawn to wrap the body. A haunted bat hung over a category title; tiles now use corner perches.
  - **Flaky e2e diagnosed instead of retried:** catches failed only in full runs. A probe test showed the Reveal completes in about 2.5 s on its own; with two parallel workers, software WebGL starved the timers. The suite now runs one worker, and if the Reveal ever stalls, the failure message reports the lunge step and saved phase.
  - **New e2e coverage:** the "Added to your cart" toast, and the "greedy" refusal past the stock limit, by day and after the Reveal.
  - **Sub-agents:** while the agent's shell was busy with a long Playwright run, it delegated polling of the log and screenshot files to a sub-agent limited to file reads.
- 2026-11-22, second feedback round from Tanvir's reference images (bat in flight and hanging, a haunted hero, a found-footage scare). The agent redrew the bat (torn red-lit wings, wrapped-wing cocoon, head that turns to follow the pointer with burning eyes), painted the haunted hero's ruined world on a canvas in code (red moon, smoke, gothic ruins, Ferris wheel, rubble, embers, an XMAS → HALLOWEEN sign), added idle haunted life to every product, a jack-o'-lantern beside the bear, inline cart confirmations instead of a popup, and the jump scare after Accept. Screenshot review drove fixes the agent would not have caught from code: the pumpkin's carved face was buried under the rind's ribs, its spill light washed the rind out, and the scare's hair strands read as prison bars.
- 2026-11-22, third round: a Take scare for every product (fx/scares), each tied to the object's story (the watch counts down your time, the typewriter types the real time and "YOU ARE NOT [alone]", the radio's roll call ends with "the one listening", the camera's Polaroid of you shows her behind you, the music-box dancer spins but her face never leaves you, and so on). The agent wrote a screenshot spec that triggers all of them in one run and reviewed every frame; that review caught the footprints walking away from the viewer instead of toward them, a teddy scene that read as a plain slit, the lunge and the final scare looking blurry because small elements were scaled up (now laid out at final size and scaled down), and the shoes not reading as shoes (rebuilt as lace-up boots). The doll's idle eye movement was removed at Tanvir's request: her one look, after you take her, is the scare.
- 2026-11-22, fourth round: Tanvir asked that every Take happen in the object itself, not as text overlays. The agent wrote the request up as a reusable prompt (`docs/prompts/round-4-feedback.md`) and built a `useTaken` hook (seconds since the take, Infinity on reload or reduced motion, so every model shows its end state honestly). Then, per model: the envelope opens on her photo and "YOU KILLED ME"; a jagged wedge is bitten out of the cake; the typewriter stops and KILL ME seeps in; the calendar shows the current month and crosses out today; the soldier snaps at 90 degrees; the radio is tuned station by station to a red "Hz" mark; the gift opens on a skull and a bat escapes the card; mittens became a rocking chair that rocks forever; a black ghost beats against the snow globe; the truffles become small heads; the music box bursts into springs and gears; the candle takes the whole page dark; the bear bleeds; shoe prints wander the page. The haunted shop got a painted backdrop with the pumpkin in it. Screenshots of each event were reviewed; they caught the letter's page leaving the frame and the globe ghost being too small to see.
- 2026-11-22, fifth round (`docs/prompts/round-5-feedback.md`, 16 items). The key finding was architectural: several Take events only appeared after the product view closed, because the view is a native modal `<dialog>` in the browser's top layer, above every z-index on the page. The agent added a `TopLayer` portal that renders effects inside the open dialog (Polaroid, ornament reflection, the teddy's sword slash, the candle's dark) and a second copy of the walking shoe prints drawn over it. Other work: the watch runs forward until taken; blood tears for the doll; the phone handset lifts to an unseen ear and bleeds; a skeleton hand climbs out of the broken soldier; a shared face-up skull model (sockets, nose hole, teeth facing up, blood) for the gift and the truffles; the teddy is beheaded by one stroke, its head rolling onto the floor; the candle blacks out the window, claws thud into the glass, and the pointer becomes the flame that lights the way to the close button; the checkout ghost cuts in already close, jerks, then lunges to fill the screen; the pumpkin went back to its grid-cell size, among a code-painted graveyard (stones, crosses, fence, dead tree, mist) with no empty floor under the shelves. A false "greedy" note on the teddy was traced to the ambient "sneak into cart" quirk, now limited to the child's drawing. A new screenshot test takes items from inside the product view to prove each event plays there.

- 2026-11-23, sixth round: a detailed bat-refinement brief from Tanvir (`docs/prompts/round-6-bat.md`). Before changing anything, the agent wrote a Playwright capture (`e2e/tests/visual-bat.spec.ts`) that measures the live bat (box, drawn silhouette, ears, feet) and draws a large copy from the same SVG. It ran this on the deployed version to get a baseline: Christmas 36 x 88 px, haunted 42 x 103 px (the two modes did not match). Both now share one size and anchor (`hangBox`, 28.8 x 70.5 px, exactly 0.8 of the Christmas bat), and the measurements confirm it on desktop and phone. The ears are half their original absolute length (0.5 / 0.8 = 0.625 inside the already-scaled drawing, to avoid compounding) and grow from the sides of the head. The drawing gained a short neck, pointed wrist corners, layered membrane shading, low-contrast bones and veins, clearer eyes, nose and mouth, and slender feet with hooked claws. The expression shapes (slits, scowl, fangs, glowing eyes) were left as they were. The same round fixed the pocket watch running forward in the full product view after it was taken; screenshots before and after the take confirm the direction.
- 2026-11-23, seventh round (`docs/prompts/round-7-flight.md`): the bat now flies at the scale it hangs at, with no grow-and-shrink. The skeleton-hand cursor is half its old size. The catch lunge starts from the bat's own flying size, and a new flying drawing was built from Tanvir's written brief: wide burgundy wings with hooked tips, layered recesses and ridges, near-black fur, small amber eyes, and relaxed legs. The reference image was not attached, so the agent said so and worked from the text. It extended the bat capture to sample the lunge every animation frame inside the page, because screenshots were too slow. That data confirmed the face ends the approach at 43 % of the viewport height. It also exposed a real bug: on a slow renderer the dark step began while the black shade was still part-transparent, because a killed GSAP tween left its inline opacity behind. The fix clears it so the stylesheet's full black takes over.
- 2026-11-24, eighth round (`docs/prompts/round-8-feedback.md`, 16 products). The pocket watch's time became a pure function of the wall clock and the stored take time (`watchClock.ts`, with a unit test), so the card and the full view can no longer drift apart; a temporary probe spec confirmed it reads the visitor's time before the take and runs backward from 2:50 after. The rest of the round rebuilt Take events in the models themselves: an instant camera that turns to you, flashes and prints; a skull on a spring in the gift and several in the music box; the calendar's blood cross, "Saint Nicholas" and claw tear; pressure dents in the chair's cushions; a genie-like shadow in the globe; the teddy cut at the throat. Findings along the way:
  - **Shader bug:** a new `matte` option for haunted leather failed to compile (`specularIntensity: no such field`), because three.js names that field differently in the physical material. It now scales `specularColor`.
  - **Transmission glass hides transparent objects:** the globe ghost was invisible in screenshots because three.js leaves transparent meshes out of the transmission pass. Its solid parts are now opaque.
  - **A stale shader kept the ornament opaque:** after the take the bauble looked unchanged. React reused the same material and only flipped `transparent`, but three.js had compiled it as opaque, which forces alpha to 1. Keying the two materials builds a new one.
  - **Screenshot review** caught chest blood that rendered as dark lumps (now a decal painted onto the fur and repainted as the bleed spreads), grey-looking pools (specular reflection at a grazing angle; now Lambert), a gift skull bouncing out of frame, chair dents too faint to see, and a capture script whose forced clicks hit a neighbouring card's Add button after a layout shift, and a retry click that opened a slow view twice so Close stepped back onto the same product.
  - **The full e2e suite caught a phone-only stall:** after the shoes were taken from a card, clicks on the phone project never completed. Lasting prints now come from the whole walk, and the walk's jitter could put some past the card's edge and off the side of the 390 px screen. Every print is now clamped inside its area, and the test passes again. The reduced-motion story test was updated to accept the lasting marks, which under reduced motion appear at once instead of walking.
  - **Lint (React Compiler rules)** flagged ref and memo misuse in the new models; each was refactored.
- 2026-11-24, ninth round (`docs/prompts/round-9-bat-reference.md`): Tanvir attached the bat reference image that round 7 had only described. The agent redrew the flying bat's wing geometry from it: a high wrist with a long hooked thumb, an outer tip, deep scallops through four finger tips, holes kept inside the scallops, a crimson scaly membrane (an SVG pattern), a shaggy torso outline, taller upright ears, and strong legs with spread claws. The lunge now grows at a constant proportional rate (size s0^(1−t)), with slow, shallow wing beats, so the approach reads as a steady glide instead of a late rush. The mid-flight swell from before round 7 came back for both the Christmas and the haunted bats. Each bat is laid out at its swollen size and scaled down, so the SVG is never enlarged from a small raster, and the haunted bats are now placed by their centre so that changing size does not make them slide. The bat capture spec was extended to sample the bat's width every frame through one flight (92 px at take-off, 152 px mid-flight) and to draw the close-up with the wings held still for comparison with the reference.
